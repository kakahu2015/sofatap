# 微信小程序 · 测试与上架手册（中文）

更新于 2026-10-21。对应 `wechat-miniprogram/`，是 HostTap 的**控制端**：用微信小程序扫码配对，通过局域网安全 TCP 控制电脑。

> 顺序建议：先做完第 1 节真机测试，再走第 2、3 节的注册与审核。没有真机通过就提交审核，大概率因“无法验证核心功能”退回。

---

## 1. 真机测试（先做这一步）

### 1.1 本地静态验证（已完成）

| 检查 | 结果 |
| --- | --- |
| JS 语法（7 个文件，`node --check`） | 全部通过 |
| JSON 配置（5 个文件） | 全部可解析 |
| 依赖安装（`crypto-js@4.2.0`） | 安装成功 |
| 配对链接解析单元测试 | **11/11 通过**（`wechat-miniprogram/tests/pairing.test.js`） |

单元测试覆盖：正常解析、无名称回退、`65535` 端口回退到 53320、中文字段往返、非 HostTap 链接、字段缺失/重复/未知、非 IPv4、端口越界、token 与 fingerprint 格式、非法平台、控制字符与超长名称、2KB 上限。

复跑命令：

```powershell
cd wechat-miniprogram
node --test tests/pairing.test.js
```

### 1.2 准备

1. 真实小程序 AppID。把 `project.config.json` 的 `touristappid` 换成它，或在开发者工具里选择。
2. 微信开发者工具（最新稳定版）。
3. 手机与电脑连**同一个 Wi-Fi**；手机用蜂窝数据一定失败，微信只允许连同一局域网内的非本机 IP。
4. 电脑端运行最新 Receiver（含 `MiniProgramServer`，监听 `控制端口 + 1`，默认 53320）。旧版只有 53319，小程序连不上。

### 1.3 步骤

```powershell
cd wechat-miniprogram
npm install
```

1. 开发者工具导入 `wechat-miniprogram` 目录。
2. **工具 → 构建 npm**，生成 `miniprogram_npm`（缺这一步会报 `crypto-js` 找不到）。
3. 详情 → 本地设置 → 勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。
4. 点“真机调试”或“预览”，手机扫码打开。
5. 电脑端确认监听：`netstat -ano | findstr 53320`。
6. 小程序点“扫描电脑二维码”，扫电脑上的配对码。

### 1.4 验收清单

逐项打勾，任一项失败先修，不要提交审核。

| # | 检查项 | 预期 |
| --- | --- | --- |
| 1 | 扫码配对 | 扫码后显示电脑名称与地址，无报错 |
| 2 | 连接 | 建立安全会话，状态显示已连接 |
| 3 | 保存电脑 | 保存后可从列表直接连接，最多 20 台 |
| 4 | 指针 | 单指移动，指针跟随；轻点触发左键 |
| 5 | 滚动 | 双指滚动，方向与 HarmonyOS 版一致 |
| 6 | 按键 | 右键、Enter、Backspace、Esc 均生效 |
| 7 | 文字发送 | 输入后发送，电脑端收到；断网时不自动重发 |
| 8 | Live Text | 焦点在普通文本框时出现编辑区，120ms 合并同步 |
| 9 | 后台/前台 | 切后台连接暂停，回前台自动恢复 |
| 10 | 单控制器 | 小程序连接时，手机原生 App 无法同时控制 |

### 1.5 已知风险

`crypto-js@4.2.0` 已被官方停止维护，`npm install` 会直接给出弃用警告。两种情况都要处理：

- 短期：锁定版本，在审核备注里说明仅用于本地加密，不访问外网。
- 中期：改用微信原生 `wx.getRandomValues` + 自实现 AES/HMAC，或换维护中的库。

## 2. 注册与备案

| 步骤 | 位置 | 要点 |
| --- | --- | --- |
| 1. 注册账号 | `mp.weixin.qq.com` → 立即注册 → 小程序 | 个人主体用身份证，企业主体需营业执照；主体类型注册后不可改 |
| 2. 完善信息 | 设置 → 基本设置 | 名称唯一；头像、简介、服务类目 |
| 3. 选服务类目 | 设置 → 基本设置 → 服务类目 | 建议「工具 → 效率」或「工具 → 设备管理」；远程控制类目可能需要额外资质，个人主体可选类目较少 |
| 4. **小程序备案** | 设置 → 基本设置 → 小程序备案 | 发布前置条件，需主体证件、负责人信息与人脸核验；审核由通信管理局完成，通常数个工作日 |
| 5. 接口权限 | 开发管理 → 接口设置 → TCP 连接 | 申请开通，理由写“连接用户自有电脑的局域网服务，数据不出内网” |
| 6. 隐私指引 | 设置 → 服务内容声明 → 用户隐私保护指引 | 勾选「摄像头」「扫码」；`app.json` 已开 `__usePrivacyCheck__` |
| 7. 成员管理 | 管理 → 成员管理 | 加开发者、体验成员 |

服务器域名不用配置：小程序走局域网 IP，不经过公网域名。若将来改用公网 WSS，则域名必须已备案且配置到「socket 合法域名」。

## 3. 上传、审核、发布

1. 开发者工具点“上传”，填版本号与备注。
2. 后台 → 管理 → 版本管理 → 开发版本设为**体验版**，先让体验成员真机走一遍第 1.4 节。
3. 体验版通过后，点“提交审核”。
4. 审核信息填写要点：
   - 功能页面：主页路径 `pages/index/index`。
   - 测试说明：写明“需在电脑端运行 HostTap Receiver，手机与电脑同一 Wi-Fi；审核员无电脑端时，可验证扫码入口、设备列表与界面渲染”。
   - 建议附一段 30–60 秒操作录屏：扫码 → 连接 → 移动 → 点击 → 发送文字。
5. 审核通过后点“发布”。发布即上线，可随时在后台回退版本。

审核周期通常 1–7 个工作日，首次会更久。

## 4. 常见退回原因

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| 未完成备案 | 跳过第 2 节第 4 步 | 先完成小程序备案 |
| 服务类目与实际功能不符 | 类目选了工具但实际是远程控制 | 改成匹配类目，或补充资质 |
| 涉及用户隐私但未声明 | 隐私指引未勾选摄像头 | 补齐声明并重新提交 |
| 无法验证核心功能 | 审核员无法配对 | 审核备注写清验证路径，附录屏 |
| 接口未开通，功能不可用 | TCP 连接未申请 | 后台接口设置里申请 |
| 页面白屏/报错 | 未构建 npm | 开发者工具“构建 npm”后重新上传 |

## 5. 需要准备的材料

1. 小程序 AppID（`project.config.json` 替换 `touristappid`）。
2. 主体证件（个人身份证 / 企业营业执照）与负责人人脸核验。
3. 服务类目选择结论。
4. 隐私保护指引文案（摄像头、扫码用途）。
5. 审核用操作录屏 30–60 秒。
6. 体验成员微信号（至少 2 个，含你自己与一名测试者）。
